# ApocaChaseCamera 0.2.0 review and build

Reviewed October 9, 2026. Compared the attached source-only proposal with the canonical 0.1.9 project and published source baseline. No newer local camera work was found. The existing camera smoothing, collision-query buffers, native compass action pipeline and rusty driving HUD are preserved. All implementation changes are inside ApocaChaseCamera.

| Issue found in proposed source | Fix and verification |
| --- | --- |
| Production build blocked by obsolete Harmony.UnpatchAll(string), which the installed Harmony 2.9.0 treats as an error | Restored owner-specific UnpatchSelf. Production builds with no warnings; real Harmony tests confirm foreign patches survive shutdown and interface failures remove this bridge's hooks. |
| Compass yielded during non-scoped ADS even though Apocaplayer still renders third person | Uses the computed active pose for that state; scoped/binocular views still yield. New ADS regression passes and fails with the original guard restored. |
| A rendered mesh road could be treated as a fadeable obstacle | TerrainCollider and named road geometry stay solid; upward-facing sweep hits never bypass collision. Added rendered-road and unnamed-ground checks. Removing the road guard reproduces the failure. |
| Boolean fade result remained valid briefly after a renderer became hidden | Cache renderer bindings and check their visibility live, including within the same frame. Hidden/disabled meshes immediately restore collision protection. |
| Blocker hierarchy arrays and ancestor-name strings were rebuilt every 0.1 seconds | Cache structural discovery for ten seconds or root changes, bounded to 1,024 colliders. The new workload test observes one hierarchy scan across 120 checks over two seconds. This is a simulation, not an in-game performance measurement. |
| Camera eligibility assumed the bound first-person camera was still Apocaplayer's owner | Validate Game.Cam and reject ownership/heading from an old camera if the owner is replaced. |
| Scene refresh could retain a valid shared pose for the remainder of the frame | Invalidate the bridge-owned cursor cache before clearing scene handoff state; new scene-refresh assertion passes. |

The proposal's main cursor-cache hook, both cutaway toggles, cave guard, wheel routing and hidden-orbit handoff were retained after review. A negative control removing the ComputeView hook reproduces cursor misalignment. The ordinary Windows test runner also passes; the additional cross-mod runner uses the locally installed Harmony without requiring an SDK or changing another mod.

## Results

- Production DLL compiled against the real local game dependencies with zero warnings.
- 3,419 simulated regression assertions passed, including 14 real prefab anchor fixtures.
- 85 cross-mod assertions passed with unchanged external ThirdPerson.cs and the installed Harmony 2.9.0. Unity/physics/cutaway/UI dependencies are simulated.
- 42 reflected field/property/method contracts verified directly against installed Apocaplayer.dll; plugin GUID/version, optional assembly dependency and production type ownership verified.
- Three negative controls failed as expected: missing cursor hook, old ADS compass guard, missing road solidity guard.
- No Apocaplayer or Apocasetter files were edited. Their installed DLL hashes are unchanged.
- The install ZIP has exactly ApocaChaseCamera/ApocaChaseCamera.dll and ApocaChaseCamera/README.md. No source, tests, third-party assemblies or game assets are in it.
